# Fixed TabPFN-v2 local prior experiment, 64 treatment wells

Built with PriorLabs-TabPFN. Research model name: TabPFN-von-DosePilot-64. This is a local experiment using Prior Labs' publicly released pretrained tabular model, not an original foundation-model claim. No model service, account, purchase or patient-data upload is involved. The existing operating product is unchanged.

## Hypothesis
A pretrained small-tabular regression prior may capture nonlinear cross-drug dependencies that the existing hand-designed own-drug/ridge/additive-kernel families miss. This is distinct from the completed pooled shared/private ridge experiment, which tied the operating baseline. There is no claim the model will halve error before testing.

## Fixed biological task
Use only the authenticated Lib1 TRAIN input: 119 organoid samples, 59 whole patients, 24 unchanged normalized log-dose AUC targets. Rebuild the existing R13 acquisition inside each of the five original outer-training patient splits. Each alternative A/B deployment purchases exactly 64 distinct native doses and 32 physical wells per source plate. Average A/B LOSSES only. No new physical measurement, assay-control input, patient/genotype identifier, clinical outcome, or excluded dose is available at inference. Protected22/Lib2 is never read.

## Candidate specification, no search
One fixed direct-AUC model family, not a menu selected on these outcomes. Train a separate TabPFN regressor for each of 24 targets. All 64 purchased values are inputs; place that target's own purchased columns first and the remaining columns in original order. Append the known binary A/B layout indicator (metadata, not a paid measurement). No extra target labels become features. Raw viability values are retained without clipping. Use two identity-only balanced context panels. In each panel each fitting patient contributes exactly one organoid and both alternative training layouts. Samples per patient are ordered by SHA256 of fixed salt plus sample ID; panel 0 selects position 0, panel 1 selects position 1 modulo that patient's sample count. Sample ordering never reads outcomes. This handles TabPFN's lack of sample-weight support by equally representing patients in each context; it is a disclosed context-subsampling procedure, not the same full-row weighted fitting objective as the incumbent. It may lose information from patients with more than two organoids.

Each context uses exactly two TabPFN ensemble estimators, no automatic estimator scaling, CPU float32 default inference, fit_preprocessors mode, one preprocessing worker, random seed 202610071519 + 1000*outer_fold + 10*target_index + context_index. Regressor settings are otherwise the published V2 defaults. Average the TWO CONTEXT-MODEL predictions for the SAME purchased query layout. Never average A and B predictions into a free larger panel. No fine tuning, residual mixing, target-wise weights, orientation-specific model choice or automatic hyperparameter search.

Because there is no outcome-selected hyperparameter, no inner model search is required. Acquisition still uses only outer-training rows. The two contexts and all target models exclude all samples from each outer-test patient. Do not retrofit a fallback or blend after seeing outer errors; report this candidate as-is.

## Scoring, target and gates
Score equal-patient/equal-target mean squared error, averaging the two layout losses; retain p90 patient RMSE and all five fold losses. Frozen reference arrays supply the operating baseline and retained research comparator only, never fitting features. References must match operating MSE 0.0010582750420801538 and retained MSE 0.001042745722096212. Halved-error target: <=0.000521372861048106 with p90 <=0.037419695944064885. Eligibility for further independent replay requires strictly lower MSE, >=30 patient wins, 5/5 favorable folds and nonworse p90 against both references, with the original physical budget. No automatic promotion or Kaggle entry change. Descriptive whole-patient bootstrap: 100000 resamples, seed 202610071519, selection-unadjusted.

## Integrity and stopping
Before candidate outcomes: run synthetic CPU compatibility/prediction tests, pin this source and checkpoint, then publicly commit the freeze. During inference no networking is allowed. Save one immutable result per target/context, context indices privately, physical outer plans, and all predictions for replay. Reject missing purchased inputs rather than invoking TabPFN imputation. Check patient disjointness and deterministic context selection. Rebuild first outer-fold/target prediction after modifying ONLY its training-ineligible labels; prediction must remain identical within 1e-6 float32 tolerance. Verify purchased-cell extraction is unchanged after poisoning every unpurchased cell. On runtime failure record an explicit failure; do not mark it as scientific rejection or rerun modified settings silently. Complete all five folds irrespective of early losses. No parameter changes from partial outcomes.

The synthetic preflight (96 rows,65 features,38 queries) took about 5.55 seconds for a two-estimator fit/predict on this CPU, showed zero first-query change when other synthetic queries changed, and made zero network attempts. These are feasibility observations, not biological performance. All biological results remain repeated adaptive development, not independent validation or clinical performance.

## Final design decision before freeze and before biological outcomes
Run two explicitly separate, fixed arms, not a result-selected blend: (1) PRIMARY full-context TabPFN, using all outer-training organoid rows and both alternative training layouts; (2) the patient-balanced two-context arm specified above. The full-context arm is the standard unweighted TabPFN fitting procedure and therefore lets patients with more training organoids contribute more context rows; its test metric remains strictly equal-patient. The balanced arm tests this trade-off by giving each fitting patient equal representation, at the cost of omitting some organoids. This is disclosed rather than pretending TabPFN has a native sample-weight API. Both arms retain exactly 64 purchased query values and the same five patient-separated folds. Report both regardless of direction and do not select per target, per fold, or per orientation after seeing outcomes. Each arm must independently meet the same retained-model gates. The two arms are defined before the first biological fit; the earlier synthetic runtime check did not read biological inputs.
